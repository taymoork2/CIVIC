# Shared component contract

The design is shared; rendering belongs to each platform. OpenDesign defines reviewable anatomy and behavior. SwiftUI, Kotlin/Compose and the web implement that contract using their own layout and accessibility mechanisms. Tailwind and StyleX are optional web implementation choices.

## Authority and exchange

- `DESIGN.md` owns visual language and laundry-domain requirements.
- `colors_and_type.css` and `tokens.css` remain the editable token source for this package. Current production and historical dictionaries retain their separate evidence roles.
- `source/tokens-light.tokens.json` and `source/tokens-dark.tokens.json` are generated DTCG 2025.10 exchange subsets, never separately maintained palettes. Source hashes and original CSS values accompany them.
- `preview/component-contract.html` composes existing kit components as interactive review examples. It is an HTML reference, not a running native app.
- Figma components and native implementations must preserve semantic IDs, anatomy and state meanings. Native conventions may change presentation while retaining task intent.

The 13 browser modules include helpers and controllers; they are not 13 independently audited visual components. This first contract covers Action row, Source row, Draft sheet and Adaptive task. No complete component-parity percentage is asserted.

## Component families

| Stable family | Anatomy / sizing | Required states and behavior |
|---|---|---|
| `action-row` | Flexible title/facts plus compact action. 12–16px gap. Existing loading specimen uses a 9rem action column; it wraps below the facts when necessary. Button height is a minimum, never a fixed text-clipping height. | Default, pressed, disabled with adjacent reason, focus, hover where available. Text receives spare space; action never stretches because its parent is flex/grid. A full-width primary requires an intentional task-footer or narrow task-layout role. |
| `source-row` | 44px media tile, title and one concise fact, upper-right dot+text status and lower-right disclosure (centered without status). 12px gap and 12px 16px grouped-row insets. Source-specific issues beneath that row. | Ready, missing fact, recorded conflict, washing, drying. Whole-row disclosure and issue actions remain separate targets. Names wrap. Red conflict is never relabeled as yellow missing information. |
| `draft-sheet` | Identity/header, scrolling form, separate actions. Narrow bottom sheet; wide modal. Minimum hit targets and stable input identity. | Clean, edited, validation failure, discard confirmation, pending, error with inline retry, saved. Close/back/Escape/swipe do not save. Keep editing retains values. Reverted drafts are clean. Multi-step drafts keep answers on Back. A fact row opens the editor at its section/field; Save and Cancel return to the same record tab (existing records stay open after Save, new records close). Pending freezes controls; an error keeps the draft and points at the field; success stays visible across parent re-renders. A kept task draft (an unsaved dryness check) is named on its row and removed only by an explicit, confirmed discard. Drafts are page-lifetime; no reload durability is claimed. Restore opener focus and preserve underlying scroll. |
| `adaptive-task` | Records/equipment before settings/steps/action in reading order. One or two purposeful columns, never three. | Narrow, wide, enlarged text, keyboard visible, orientation/posture change. Reflow never remounts drafts or restarts timers. Physical starts require an explicit record after the user starts equipment. |
| `choice-tile` | Art above a short visible label inside a labeled group (`role="group"` named by a visible legend or the step heading). Up to N columns with a 4.5rem tile floor, so enlarged text drops columns instead of squeezing labels. 76px minimum height, 14px corner, 32px art. | Toggle semantics (`aria-pressed`); accessible name = visible label. Selected = selection fill + accent ring + check badge, never color alone. Only for recognizable categories: clothing type (4 columns) and product form (3 × 2). Short answers stay chips; sentence answers stay radio cards. |
| `choice-chip` | Three variants of one control: text chip (44px, 16px corner, inline), answer chip (full-width 56px row) and care-symbol tile (art above words, check in the corner). Rows sit under a visible label in a labeled group. | Toggle semantics (`aria-pressed`). One selected treatment for every variant: accent (selection) fill + selected ring + a check mark, never color alone. Pressed scales to .97 with motion allowed; disabled dims. |
| `answer-row` | Two or three short answers to one question in one row of equal-width buttons, under a visible question. 44px minimum height (48px in a task footer), 8px gap, content-sized text that wraps. | Wraps onto a second row (columns of at least 5.5rem) at large text, never a stack of full-width bars. Chosen answer is filled and `aria-pressed`; a plain action is outline; at most one filled primary. Group named for assistive technology. Use for “Gone · Lighter · Still there”, “Put them together · Keep apart”, “Hang them · Wait for one”. |
| `segment-choice` | One choice out of a few kept as a setting: the shared segment control, equal segments with a 4.5rem floor. | Radio-group semantics, wraps under large text, answers or saves on tap, disabled while saving. Use for loads a day, rack size, “Washers free” and “Dryers free” (1 · 2 · 3+), and a piece's Dry · Hang it · Not yet. |
| `action-list` | Three or more actions, phrase answers or a menu as one grouped card of divider rows: title, optional hint, optional end caret. | Recommended action first; rare or final actions last and quiet (“Retire it”). A caret marks a row that opens something. Two actions use `answer-row` instead. Never a column of separate outline buttons. |
| `garment-icon` | One line icon per clothing type from the canonical 17-glyph set in `DESIGN.md` (Garment icons): 24-unit grid, no fill, 1.6 stroke, round caps; 24px in a row, 36px in a sheet header; an optional colour dot at the bottom corner (44% of the icon). | Decorative (`aria-hidden`); the row or tile names the garment. Unknown type draws Other (a plain hanger outline). No shading, no photograph. The dot appears only where a colour is meant (never on type tiles) and never carries meaning alone. |
| `type-picker` | The clothing type step for intake and Edit: “Search clothing” field (placeholder “e.g. hoodie or leggings”) above a 4-column `choice-tile` grid of the 16 care types (Bodysuit only with a baby wearer). Typing replaces the grid with up to 8 article rows: type art, article name, muted type word. | Empty search shows every tile, no pagination. Each row is named “{Article}, {Type}”; a polite, visually hidden count reports matches; no match offers one Add “{words}” as Other row; Enter picks the first row. In intake an article names an untouched garment “{Color} {article}”; in Edit it changes only the type and never renames. |
| `action-feedback` | A success is a brief toast. A failure is an inline `role="alert"` banner (conflict tone) next to the section that acted, with a “Try again” action. | The banner holds until the next attempt or an edit; it never auto-dismisses. Try again repeats the same work and is omitted when repeating could duplicate a record (adding an appliance). Pending disables Try again. No error toast. |
| `grouped-secondary-actions` | Under a task instruction, in order: an explanation disclosure with a quiet, semibold, never-underlined link-weight trigger named by what it explains (“Why here?” / “Why now?”); a “Step options” disclosure for departures from the instruction (Used a different amount, Skip, I missed it); a labeled recovery group “Something wrong?” of compact full-width rows (Ran out? Switch product, Machine problem?). | Each group is omitted when empty. Options and recovery rows are outline, never filled; the step keeps one filled primary per viewport in its task footer. The options disclosure can stay open when the user returns from a sub-step. |
| `load-summary` | One compact card: a line with the stage mark (dot + words), “From {washers}” naming every wash a dryer run combines, and the piece count; then the contents with matching pieces grouped (“White cotton tee ×2”, guests marked), ending in at most one next-action link with a 44px target. | Same anatomy at every stage (session page, running-load sheet, dryness check and put-away headers). The step and running page heading carries only the title and, once started, the start time; the summary carries the stage and origin, so the page never shows two status marks. A load is as far along as its least advanced piece. The link appears only where the screen has no other primary. Presentation only: it never records anything, and a stage word never says dry or put away unless someone recorded it. |

`choice-tile`, `choice-chip`, `type-picker` (all 16 tiles and a “sweat” results state), `action-feedback`, `grouped-secondary-actions`, `answer-row`, `segment-choice`, `action-list` and `garment-icon` (all 17 glyphs) are demonstrated in `preview/components-buttons.html` (simulated controls); the product-form grid also appears in `preview/chemistry-records.html` and the intake type step with live search in `preview/production-patterns.html`. `load-summary` and the shared care-history list are demonstrated in `preview/production-patterns.html` (Load summary across stages). The dose figure appears in its wash preparation step, the stain follow-up groups in its garment record and the water setting in its Household water card; the stained drying case is in `preview/dryer-handoff.html`. The Next card, day plan and strip, shared start counts and Laundry day settings are in its Laundry day card; the dryer wait, None free with its machine entry, the dryer step (paid blocks and heat), dryer share line and the Take out early screen are cases in `preview/dryer-handoff.html`.

`action-row`'s 9rem width is a reviewed loading-action example, not a universal button token. Longer labels/localization use content-driven compact sizing or wrap onto their own line. Enlarged text may switch layout earlier.

## Platform mapping

| Concern | OpenDesign / browser kit | SwiftUI | Kotlin / Compose | Figma |
|---|---|---|---|---|
| Semantic colors | CSS role variables, explicit day/night pairs | Named color roles with light/dark values | Custom theme color roles | Same variable names in Light/Dark modes |
| Logical spacing | CSS px at baseline; rem for text/layout threshold | Points, adaptive layout | dp; window constraints | Number variables; Auto Layout padding/gap |
| Text | Source Sans 3 tasks; Source Serif 4 identity; rem | Licensed native font files plus Dynamic Type text-style mapping | Licensed font resources plus sp/font-scale behavior | Installed licensed fonts and matching text styles |
| Touch targets | At least 44 CSS px; primary 48 | At least 44pt | At least 48dp | Min-size specs annotated per target |
| Action sizing | Intrinsic/compact width; growing text sibling | Content-sized action; text receives available layout priority | Content-sized action; weighted text area, stable state | Auto Layout action hugs contents; text fills container |
| Draft sheet | CareSheet + native HTML dialog | Native sheet/presentation; dismissal routed through draft guard | Native modal sheet/dialog; Back/dismiss routed through draft guard | Component variants and prototype discard branch |
| Wide task | Container query at 48rem; cap 72rem | Choose from available width and text size | Available window space and folding features | Compact/expanded examples with resize constraints |
| Input and navigation | Browser focus and keyboard behavior | Native keyboard, safe areas, VoiceOver | Native keyboard, insets, TalkBack | Document behaviors; prototype does not prove them |

Numbers translate as logical dimensions, not physical pixel equality. A 48rem web threshold is not automatically a native breakpoint; choose two panes only when records and settings remain readable at the current text scale. Platform adapters own safe areas, keyboard avoidance, segment geometry and accessibility targets. See `source/foldable-layout.md`.

## Font boundary

The project currently includes web WOFF2 files and OFL licenses. Figma and native apps need compatible installed/bundled font files. Acquire TTF/OTF from the exact upstream revisions recorded in `source/font-manifest.json`, retain licenses, inspect registered names/weights and test glyphs, italics and text scaling. The exchange files carry family names; they do not install fonts or establish native font acceptance.

## Figma handoff

Figma's documented importer accepts DTCG JSON modes. Import both generated files together into a variable collection so the shared token names receive Light/Dark values. Check the resulting mode names, variable names, colors and alpha. Dimensions use px and durations use seconds to fit the documented importer; rem originals and the 16px reference conversion remain in metadata. Create text styles and component variants separately.

For the four families, use these component names: `LC/Action row`, `LC/Source row`, `LC/Draft sheet`, `LC/Adaptive task`. Use variants for genuine state changes and Auto Layout for reflow. Keep buttons on Hug contents and the informational sibling on Fill container; use minimum height and allow text wrapping. Preserve source-row grouping and the dirty-dismissal prototype branch.

Imports have not been executed in Figma this turn. Token import does not create components or bind every text style automatically. Do not treat matching tokens as proof of matching layout.

## OpenDesign and Claude Design handoff

Use the same current contract, CSS and component specimens in both tools. Reuse named kit modules rather than reproducing each row's markup on every screen. Historical Claude Design imports remain lineage evidence, not a second editable master. Pass the contract and current assets with any new design brief; record tool-specific deviations explicitly.

There is no automatic two-way synchronization established among OpenDesign, Claude Design, Figma or native repositories. Review changes here, update the canonical source, regenerate the exchange files, then integrate and verify each adapter. Exported or imported edits do not silently replace canonical values.

## Regeneration and drift check

From this project, run `"$OD_NODE_BIN" source/export-design-tokens.mjs` to regenerate the two exchange files. Run the same command with `--check` to detect stale or edited exports. `source/verify-package.mjs` remains the bounded kit logic/link/asset check and also checks catalog alignment and the owner of shared tab styles. `source/verify-component-contract.mjs` checks the specimen's invalid-draft rejection, explicit save, source-status update and inspection of the saved fact in a bounded host simulation.

The exchange subset covers semantic colors, spacing, radii, baseline size roles, typography sizes/families/weights/leading, and selected interaction durations. It omits shadows, glass materials, derived hover colors, easing, font binaries and component behavior. Those still require the CSS, this contract and platform-specific adaptation. Reduced motion removes motion rather than switching color modes.

## Change discipline

Change the authoritative rule or implementation once, then update affected specimens and handoff files. Keep historical sources immutable. Regenerate exchange values from CSS; do not edit exports independently. Review names and categories come from manifest.json; the overview and preview manifest mirror it. Do not add another top-level “start here” for each refinement.

Keep the existing palette, typography and state meanings unless the owner changes them. Consolidation is not a styling-framework migration or evidence of native acceptance. Prior revision copies explain change history; current rules describe the final behavior without repeating the chronological debate.

## Acceptance before claiming parity

Review the same four families in light/dark, short/long content, normal/enlarged text, empty/error/disabled/selected states, keyboard and touch. Compare text wrapping, logical insets, growing row height, action width and primary-action count. Test edited-sheet dismissal and fold/unfold with input state intact. Use platform accessibility tools and real runtime evidence.

The browser specimen proves only its displayed browser reference. Figma prototype, SwiftUI and Compose parity, native font integration, physical foldables and cross-platform screenshots remain unverified. Do not count an implementation as matched because its hex values match.

## Styling-tool decision

Keep the current web styling until a bounded pilot shows a concrete benefit. StyleX supplies compile-time CSS, typed styles/themes and predictable composition for web applications; it does not implement SwiftUI or Compose layouts. Evaluate one action row and one draft sheet against this contract before considering a migration. Compare overrides, build integration, bundle output, accessibility and maintenance effort. No migration is approved or performed by this contract.
